# 悬浮窗口实时排名

在悬浮窗口顶部齿轮中开启「显示实时排名」。默认关闭，开启后显示前 3 行和当前选手；前 K 行可设为 1–20。拖动榜单标题调整位置，位置和显示设置保存在本机，重新打开悬浮窗口后恢复。

## 展示与交互

- 以当前比赛、赛段、组别、轮次作为独立排名范围，标题显示赛段、组别、轮次。
- 显示名次、选手名称、两位小数的得分。长名称截断，悬停可看完整名称。
- 当前选手高亮。当前选手在前 K 行之外时，追加当前选手行；中间有被省略的选手时显示省略人数。当前选手进入前 K 后只出现一次。
- 尚未产生计分事件的当前选手显示「待计分」，不赋予虚假的零分名次。已完成的零分成绩参与排名；待上场与作废轮次不参与排名或归一化最高分计算。
- 同分采用竞赛排名，例如 1、2、2、4。按最终显示的两位小数判断同分；同分行按出场顺序稳定排列。K 表示行数，并列不会自动扩展榜单高度。
- 排名标记「实时 / 暂定」。归一化的分母会随裁判组内最高分变化，因此其他选手的实时得分也可能变化。
- 设置中可调整归一化满分（默认 60，范围 1–100）和重点扣分开关。长榜单在可用窗口区域内滚动。

## 统一的计算规则

悬浮榜单、报表和 CSV 的归一化、重点扣分与并列规则统一使用 `src/shared/ranking.mts`：

1. 对每位裁判，取排名范围内有效选手的最高原始总分，最低按 0 处理。
2. 最高分大于 0 时，将该裁判给选手的总分除以最高分，再乘归一化满分；否则该裁判的归一化得分为 0。
3. 对所有配置的裁判取平均。尚无计分的裁判按 0 计算，分母始终为裁判总数。
4. 开启重点扣分时，只收集双机裁判的重点扣分，取众数；多个众数取较大值，再从平均分中减去该值。
5. 得分保留两位小数后排序、分配并列名次。

报表与 CSV 现有入口仍展示首个赛段的第 1 轮。实时榜单使用当前比赛上下文，不复用这个入口，也不混合不同赛段、轮次的成绩。报表页面和榜单的满分值、扣分开关分别设置；比较结果时需使用相同参数及范围。

## 计分与持久化

- 每条裁判事件仍独立保存为不可变的 `score_events`，按事件 ID 去重。
- 新增 `score_snapshots`，主键为 `(match_session_id, referee_id)`。写入事件与更新该裁判快照在同一 SQLite 事务中提交；失败时一并回滚。提交成功后才更新运行时分数并通知界面。
- 快照以提交顺序更新，不使用时间戳或随机事件 ID 推断最后一次计分，避免同毫秒按键读到错误成绩。
- 排名查询只读取当前组别、轮次的裁判快照，不扫描计分事件历史。报表和 CSV 的当前成绩也读取快照；明细、回放仍读取事件历史。
- 高频按键只合并排名查询与 IPC 广播，最多约每 33ms 刷新一次；原始计分事件不节流、不丢弃。开始比赛、切换选手、清零、完成、作废会立即刷新并取消待执行的旧刷新。
- 清零将系统清零审计事件与所有裁判零分快照放在同一事务中，成功后才更新界面。重新进入已有成绩的选手进行重评时，在激活上下文的事务中清零原快照，与运行时从零计分保持一致。
- 在连接计分设备前激活并初始化持久化上下文，避免连接过程中收到的首个按键被后续初始化覆盖。
- 排名读取失败时清空榜单并记录错误，避免继续展示过期排名；计分写入失败时不将未保存的分数发布到界面。
- 悬浮窗口只通过专用的 Next、清零 IPC 控制当前比赛，主进程验证发送者必须为悬浮窗口。自由模式在最后一位后可追加选手；赛事模式提示已到最后一位。

## 数据库结构

Schema 版本为 **5**。没有迁移、旧字段回退或兼容读取层。沿用数据库连接已有的版本检查机制：旧版本数据库在再次打开时备份后重建，不导入旧比赛数据。

## 验证

`npm test` 包含排名算法和真实 SQLite / MatchSession 链路测试，覆盖归一化、重点扣分、并列、榜外当前选手、高频事件、重复事件、事务回滚、清零、重评、作废、赛段和轮次隔离、重开数据库恢复，以及设备连接期间的首个计分事件。

另检查 `npm run typecheck`、`npm run build`，并在隔离的 Electron 预览中手工验证设置、Top K、开关、模拟加分、并列高亮、名称截断和拖动。真实硬件及透明窗口的系统鼠标穿透仍需接入裁判设备后验证。
